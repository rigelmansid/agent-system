# /profile 的领域预设

只在用户选了“领域预设”时读。预设只是起点：选完复制成用户自己的 `my-xxx`，之后怎么改都不影响
别人，它不是官方 profile（D-58）。

每个预设写了：说明（PROFILE.md 第一行的一句话）、结构（括号里是英文文件夹名）、额外文件、完成
标准、收尾、命名、git，有的还有注意事项。标了“资料类”的文件夹，第 4 轮问要不要放到
`../materials/`。各类在第 1 轮的分组：调研与写作（调研、写作）、设计与建筑（设计、建筑）、
科学实验（湿实验、物理与仪器）、财务与法律（财务、法律案件）。

## 调研

- 说明：调研项目：行业研究、市场调研、文献综述，交付调研报告
- 结构：`01_问题与范围/`（`01_scope`）研究问题、范围、交付要求；`02_摘录与笔记/`（`02_notes`）
  资料的摘录和笔记，原件放 `../materials/refs/`；`03_数据与分析/`（`03_analysis`）数据表、图表、
  分析过程；`04_报告/`（`04_report`）报告草稿与定稿
- 额外文件：`docs/sources.md` 资料索引：编号、标题、作者或机构、日期、链接或存放位置
- 完成标准：报告里的每个结论能追到 sources.md 的出处；数据写明来源和日期；报告格式符合交付要求
- 收尾：新用到的资料补进 sources.md
- 命名：`YYYYMMDD_主题_v01`
- git：不用

## 写作

- 说明：写作项目：文章、书稿、课程讲义
- 结构：`01_大纲/`（`01_outline`）；`02_草稿/`（`02_drafts`）一章或一节一个文件；`03_定稿/`
  （`03_final`）；`04_素材/`（`04_assets`）配图、图表
- 额外文件：`docs/sources.md` 引用出处
- 完成标准：字数和格式符合要求；引用都有出处；术语和称呼前后一致；通读一遍没有错漏
- 收尾：在当前状态里写各章进度
- 命名：`章节号_标题`，定稿加日期 `_YYYYMMDD`
- git：可选（纯文本稿适合用 git 看改动），默认不用

## 设计

- 说明：设计项目：品牌、视觉、网页和界面设计，交付设计稿和导出文件
- 结构：`01_需求/`（`01_brief`）需求说明和确认记录；`02_参考/`（`02_references`，资料类）情绪板、
  竞品截图；`03_概念/`（`03_concepts`）草图、概念方向；`04_设计稿/`（`04_design`）源文件；
  `05_交付/`（`05_delivery`）导出文件、切图、设计规范
- 额外文件：`docs/deliveries.md` 交付记录：日期、版本、内容、交给谁
- 完成标准：交付清单齐全；尺寸、格式、色彩模式符合要求；导出文件和源文件是同一版本
- 收尾：更新交付记录
- 命名：`项目_内容_v01`，交付文件加日期
- git：不用（源文件大）

## 建筑

- 说明：建筑设计项目：按设计阶段管理图纸、模型和往来文件
- 先点选阶段划分，每个选项的预览是对应的结构：
  - 国内三阶段（推荐）：`00_前期/`（`00_pre-design`）任务书、场地资料、规范条文（资料类）；
    `01_方案设计/`（`01_scheme`）；`02_初步设计/`（`02_preliminary`）；`03_施工图设计/`
    （`03_construction-docs`）；`04_施工配合/`（`04_site-support`）变更、洽商、现场问题
  - RIBA Plan of Work 2020：`0_Strategic-Definition/`、`1_Preparation-Briefing/`、
    `2_Concept-Design/`、`3_Spatial-Coordination/`、`4_Technical-Design/`、
    `5_Manufacturing-Construction/`、`6_Handover/`、`7_Use/`
  - AIA 设计阶段：`01_SD/`（Schematic Design）、`02_DD/`（Design Development）、`03_CD/`
    （Construction Documents）、`04_Bidding/`、`05_CA/`（Construction Administration）
  - 三种都加：`往来文件/`（`correspondence`）会议纪要、函件、提资
- 额外文件：`docs/drawing-register.md` 图纸目录：图号、图名、版次、日期、状态
- 完成标准：图纸目录和实际文件一致；改过的图纸已更新版次和日期；变更都有记录
- 收尾：更新图纸目录；新的会议纪要放进往来文件
- 命名：`图号_图名_版次`（如 `A-101_一层平面_R02`）
- git：不用（DWG、RVT 等文件大）

## 实验

先点选：湿实验（生物、化学）/ 物理与仪器。两者结构相同，额外文件不同。

- 说明：科学实验项目：从实验设计、原始数据到分析和报告
- 结构：`01_实验设计/`（`01_protocols`）假设、方案、操作规程（带版本）；`02_原始数据/`
  （`02_raw-data`）仪器导出的原始文件，只读，不改不删；`03_处理数据/`（`03_processed-data`）
  处理后的数据，注明由哪份原始数据得来；`04_分析/`（`04_analysis`）分析脚本、notebook；
  `05_结果/`（`05_results`）图表、结果汇总；`06_报告/`（`06_reports`）论文、报告、组会材料
- 额外文件：`docs/lab-notebook.md` 实验记录：按日期写目的、条件、步骤和偏差、结果、样品或数据
  编号；湿实验加 `docs/samples.md` 样品与试剂：编号、来源、批号、存放位置；物理与仪器加
  `docs/instruments.md` 仪器与校准：型号、参数、校准日期
- 完成标准：每个结果能追到原始数据和实验记录里的日期；处理和分析步骤能复现；原始数据没有被
  修改
- 收尾：实验记录补上本次的实验
- 命名：`YYYYMMDD_实验编号_内容`
- git：可选（管文档和分析脚本）；用 git 时把 `02_原始数据/`、`03_处理数据/` 写进 `template/gitignore`
- 注意：涉及受试者或患者的数据，个人信息不写进项目文档

## 财务

- 说明：财务项目：预算、记账、报表、报税或审计准备
- 结构：`01_原始凭证/`（`01_source-documents`）发票、银行流水、合同，只读；`02_账目/`
  （`02_ledgers`）台账、明细表；`03_报表/`（`03_statements`）月报、年报、预算；`04_分析/`
  （`04_analysis`）；`05_报送/`（`05_filings`）报税、审计、给出资方的正式文件
- 额外文件：`docs/open-items.md` 待核对事项：日期、金额、问题、状态
- 完成标准：合计和勾稽关系对得上；每个数字能追到凭证；期间、币种和口径写清楚；涉及税务判断的
  结论标注“待专业人士确认”
- 收尾：更新待核对事项
- 命名：`YYYY-MM_内容`（按会计期间）
- git：不用
- 注意：银行账号、税号、证件号只写在 `private-notes.md`，项目文档里用占位符

## 法律案件

- 说明：法律案件项目：诉讼、仲裁、合同纠纷，管理材料、证据、文书和期限
- 结构：`01_案件材料/`（`01_case-files`）起诉状、答辩状、对方提交的材料，按来源分；`02_证据/`
  （`02_evidence`）证据扫描件和证据目录；`03_法律检索/`（`03_research`）法条、案例检索结果和
  研究备忘；`04_文书/`（`04_drafts`）我方起草的文书，草稿与定稿；`05_往来/`（`05_correspondence`）
  与法院、对方、当事人的函件和沟通记录；`06_庭审/`（`06_hearings`）开庭准备、庭审笔录
- 额外文件：`docs/timeline.md` 事实与程序时间线：日期、事件、出处（证据编号）；`docs/deadlines.md`
  期限表：期限（举证、答辩、上诉等）、截止日期、依据、状态
- 完成标准：每个事实陈述都有证据编号；引用的法条写明名称、条号和施行日期；期限已核对；法律
  结论由用户确认
- 收尾：核对期限表，30 天内到期的写进 Handoff 的 Next
- 命名：`YYYYMMDD_文书名_v01`；证据 `证据01_名称`
- git：不用
- 注意：当事人姓名、证件号、联系方式只写在 `private-notes.md`，项目文档里用代称（当事人 A）
