# /resume：恢复项目状态

按 `~/agent-system/RULE.md` 第 1.1 节执行。只读，不修改任何文件。

## 步骤

1. 读项目 `AGENTS.md`；若开头有 `<!-- profile: code -->`，再读
   `~/agent-system/profiles/code.md`（本会话已读过就跳过）。
2. 读 `docs/project-notes.md` 的「进行中」区块和待办章节。SessionStart hook 已注入
   的内容不必重复读取，但要核对它和文件当前内容一致。
3. 「进行中」里引用的决策编号，到 `docs/decisions.md` 读对应条目；再看最后 3 条决策，
   了解最近定了什么。
4. 运行 `git status --short` 与 `git log --oneline -5`。有未提交的修改时，判断它们是否
   属于「进行中」的任务。
5. 「进行中」缺失、过时（更新时间早于最近的提交），或与 git 状态矛盾时，如实指出，
   并根据提交和文件推断当前状态。不要让用户重复能从仓库推断出的信息。

## 输出

不超过 8 行，用这个格式，然后停下等用户确认：

```text
上次停在：……
相关决策：D-n 标题（一句话），……
未提交的修改：无 | 有 N 个文件，属于/不属于进行中的任务
等你确认：……（没有就写“无”）
我打算先做：……
```

用户带着具体任务调用时（`/resume 做 X`），“我打算先做”按用户的任务写，并指出它和
「进行中」的下一步是否冲突。
